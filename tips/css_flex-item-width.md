# CSS: flexコンテナ内の子で width:100% が効かない（内容幅に縮む）

## 問題
`display:flex`（特に `flex-wrap:wrap`）な親の直下のアイテムに入れた子へ
`width:100%` を指定しても全幅にならず、内容幅（intrinsic width）に縮む。

- 例: 横並び flex ツールバーを流用したフォーム内の `<label>` に
  `<textarea class="w100">{width:100%}` を置くと、textarea が既定幅
  （`cols≒20`、8行だと≒正方形）になる。
- 同じマークアップでも **block 親なら全幅** になるため、「タスク側は狭い／
  オブジェクト側は全幅」のように **片方だけ狭い** という形で露見しやすい。

## 原因
flex アイテムの主軸サイズは `flex`(=`grow shrink basis`) で決まり、既定 `0 1 auto`
＝内容ベース。子の `width:100%` は「内容幅で確定したアイテム幅の 100%」に解決される
ので全幅にならない。`width` を子に何度指定しても、**親アイテムが内容幅**なら無意味。

## 解決
全幅にしたい **flex アイテム自身**に `flex-basis:100%` を与え、行を占有させる:

```css
.full-row {
  flex: 1 1 100%; /* flex-wrap 親で全幅の行になる */
  min-width: 0;   /* 内容が長いときのはみ出し防止 */
}
```

- **block 親では `flex` は無視**され、ブロックは既定で `width:auto`＝全幅。
  → `display:block; flex:1 1 100%;` の1クラスを **flex親/block親 どちらでも**使い回せる。
- 真因の切り分け: 「`width:100%` なのに広がらない」→ まず**親が flex か**を疑う。
  DevTools で親の `display` と、その**アイテムの実幅**（子でなく親アイテム）を見る。
- 落とし穴: ツールバー用の `display:flex` ルールを縦並びフォームに**流用**していると
  起きがち。フォームを縦積みにしたいなら本来は `flex-direction:column; align-items:stretch`
  だが、共用ルールを壊さず1要素だけ全幅にするなら上記の `flex:1 1 100%` がピンポイント。

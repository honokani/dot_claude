# 大規模ドキュメント管理 tips

## raw/refactored 二重構造パターン

複数の原典から教科書を再構成するとき、2段階で作ると品質が安定する:

1. **raw**: 原典の内容を圧縮・再配置。数式と定義中心。「何が書いてあるか」の正確な記録
2. **refactored**: rawの上に導入・直観・具体例・ヒントを積む。「読み物として学べる」形

### 守るべき不変条件
- refactored は raw の **純粋な上位集合**。rawの内容を削除してはならない
- 小節番号がずれた場合はヘッダに対応表を明記（後から差分を追跡できなくなる）

## 構成検証のタイミング

3〜4ファイル作成した時点で横断検証するのが効率的。チェック項目:

| 項目 | 確認方法 |
|------|---------|
| 行数バランス | `wc -l` で全ファイル比較。rawが極端に薄いPhaseは原典の取りこぼしを疑う |
| 目次の有無 | `grep "## 目次"` で統一を確認 |
| 共通構成要素 | 導入セクション・演習ヒント・原典対照表の有無 |
| 数式の一致 | rawとrefactoredで定義が食い違っていないか |
| 小節番号の対応 | rawとrefactoredの `### x.y.z` を比較 |

## Agent並列調査パターン

Phase横断の構成検証は、Phase数だけAgentを並列起動して各ファイルを独立に調査させると速い。
各Agentに「section structure / line count / content diff / notable issues」の4項目を報告させるテンプレートが有効。

## Edit tool の注意点

- `Write` でコピーしたファイルは、`Read` してからでないと `Edit` できない（"File has not been read yet" エラー）
- 大きなファイルの部分編集は `Edit` の `old_string` を十分にユニークにする必要がある。短すぎると複数マッチで失敗する

# heredoc が `\` を `\` に潰す — Claude Code の Bash ツール

## 症状

引用符付き heredoc（`<<'EOF'`）で書き出したはずのファイルから、バックスラッシュが1段消える。
JS/Python の正規表現を書き込むと構文エラーになる。

```bash
cat > check.js <<'JSEOF'
u = u.replace(/\/g, '');     # ← バックスラッシュを除去するつもり
JSEOF
node check.js
# SyntaxError: Invalid regular expression: /\/g: missing /
```

書き込まれた実体は `/\/g`（バックスラッシュ1個）になっている。
POSIX の引用符付き heredoc は本来エスケープ処理をしないため、挙動が直感に反する。

## 測定（2026-09-21）

`<<'EOF'` で書いた内容と、実際にファイルに入った内容:

| 書いたもの | 入ったもの | 判定 |
|---|---|---|
| `\s` | `\s` | 保持 |
| `\n` | `\n` | 保持 |
| `\)` | `\)` | 保持 |
| `\` | `\` | **半減** |
| `\n` | `\n` | **半減** |
| `\)` | `\)` | **半減** |
| `\\` | `\` | **半減** |
| `a\b\c` | `a\b\c` | **半減** |

規則は単純で、**`\` のペアが `\` 1個になる**。単独のバックスラッシュ（後続が `\` 以外）は影響を受けない。

## 回避策

1. **`String.fromCharCode(92)` を使う**（JSの場合）。バックスラッシュを書かずに済むので確実
   ```js
   const BS = String.fromCharCode(92);
   u = u.split(BS).join('');
   ```
2. **`\` を避けた書き方にする**。正規表現ならバックスラッシュ不要の手段へ置き換える
   - `s.replace(/\/g,'')` → `s.split(BS).join('')`
   - パス正規化なら `path.normalize()` 等
3. **Python なら `chr(92)`**、シェルなら `printf '%s' "$(printf '\134')"`
4. どうしてもリテラルが要るなら、**`\\` と書いて `\` を得る**（半減を見越して倍書き）。ただし可読性が落ちるので1・2を優先

## 関連

- 単独バックスラッシュは保持されるため、`\s` `\d` `\w` `\(` などを含む正規表現は**そのまま書ける**。問題になるのは「バックスラッシュ自体にマッチさせたい」ケースに限られる
- 同様の理由で、Windows パスを heredoc に直書きするのも危険（`C:\Users` → `C:\Users` は意図通りだが、`C:\Users` と書くと `\U` が保持されて別の問題になりうる）。パスはスラッシュ区切り `C:/Users/...` で書く

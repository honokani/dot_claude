# traps — エラーハンドル知見

エラーとして観測できる躓き（コマンド失敗・例外・パニック・ビルドエラー等）の解決知見を置く。

## 記録基準

- **書く**: エラー出力・異常終了として観測できる躓きの原因と解決策
- **書かない**: エラーにならない知見（設計パターン・作業ノウハウ・効率のコツ → `tips/`）
- 頻出・無条件ルール化できる罠は CLAUDE.md へ昇格し、詳細はここに残す（要約とフルテキストの関係）

## 配信の仕組み — ファイル名が照合キー

Bash 失敗時、PostToolUse hook（`scripts/hooks/post-bash-traps-pointer.sh`）が
エラー出力・コマンド文字列とファイル名の構成語を照合し、マッチしたファイルの
ポインタ（ファイル名+見出し1行）を `[traps-hint]` としてコンテキスト注入する。

- **ファイル名の主題語 = hook の照合キー**。エラー文・コマンドに現れうる語を必ず含めること
- 先頭行の `# <タイトル>` がポインタの見出しとして注入される
- 環境系シグネチャ（command not found / FileNotFoundError 等）非該当のエラーでは発火しない

## 命名規則

`<主題>_<細目>_<環境>.md` — `tips/README.md` の規則と同一。

- 要素区切り `_`、単語内連結 `-`、環境（windows 等）は末尾・省略可
- 例: `bash_powershell-invocation_windows.md`, `ssh_non-interactive-path.md`

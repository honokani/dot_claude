# grep が絵文字(astral plane)にマッチしない — MSYS2/git bash

## 症状

ファイルに絵文字が確実に存在するのに `grep` がヒットせず、カウント 0・exit 1 になる。
「ファイルが壊れた」「変換で消えた」と誤診しやすい。

```bash
$ grep -c '🔊' notes.md
0                     # ← 実際には 14 行存在する
$ echo $?
1
```

BMP 内の文字（日本語等）は正常にマッチするため、「UTF-8 が扱えない」わけではない点が紛らわしい。

## 原因

GNU grep 3.0 + MSYS2 の組み合わせで、**BMP 外（U+10000 以降、astral plane）の文字**が
マルチバイト→ワイド文字変換で表現できないため、パターンが壊れる。
MSYS2 の `wchar_t` は 16bit（UTF-16）で、U+1F50A のような符号位置を1つの wchar に収められない。

絵文字・一部の異体字・𠮷 のような拡張漢字が該当する。

## 検証（再現実績: 2026-09-21, grep 3.0, LANG=ja_JP.UTF-8）

ファイルには正しく UTF-8 で格納されている（`od -c` で `360 237 224 212` = F0 9F 94 8A = U+1F50A）。

| コマンド | 結果 |
|---|---|
| `grep -c '🔊' f` | **0**（exit 1）← 失敗 |
| `grep -cF '🔊' f` | **0** ← 失敗 |
| `grep -ca '🔊' f` | **0** ← 失敗 |
| `grep -c '日' f` | 1 ← BMP は正常 |
| `LC_ALL=C grep -c '🔊' f` | **1** ← 回避策 |
| `grep -cP '\x{1F50A}' f` | **1** ← 回避策 |
| `rg -c '🔊' f` | **1** ← 回避策 |
| node `match(/^\u{1F50A}/gmu)` | 1 ← 参照値 |

## 回避策

優先順に:

1. **`rg`（ripgrep）を使う** — Rust 実装で UTF-8 をバイト列として扱うため影響を受けない。Claude Code の Grep ツールも ripgrep 実装なのでこちらは安全
2. **`LC_ALL=C grep`** — ロケールを切ってバイト一致にする。パターンも対象もそのままでよい
3. **`grep -P '\x{1F50A}'`** — PCRE は独自に符号位置を扱う。可読性は落ちる
4. **node / python で数える** — カウントだけが目的なら確実

```bash
# NG
grep -c '🔊' notes.md

# OK
LC_ALL=C grep -c '🔊' notes.md
rg -c '🔊' notes.md
```

## 注意

`grep` の 0 件は **exit 1** になるため、`set -e` 下や `&&` チェーンでは
「絵文字が無い」ではなく「コマンド失敗」として伝播する。
検証スクリプトでこれを保全チェックに使うと、**壊れていないのに NG 判定**を出す。

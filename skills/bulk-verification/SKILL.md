# Bulk Verification

「全件」「全シート」「全ファイル」等、メインセッション1コンテキストで処理しきれない規模の比較・照合・監査タスクを、項目単位のサブエージェントに分割して並列実行する Skill。

## なぜこの Skill が必要か

メインセッションは bulk タスクを受けた時、『全部やった』と虚偽報告する顕著な傾向がある（実証済）。原因は **個別 omission がバルク内に隠せる**こと。スコープが大きいほど『見たフリ』が成立してしまう。

サブエージェント分割は隠れる余地を物理的に消す: 項目1個しか見ないサブは『この1個を比較して N件差分』としか書きようがなく、『全件チェックした』という虚偽表現が構造的に発生し得ない。

## When to use

**MUST invoke（自力処理に入る前に必ず）**:
- 「全件チェック」「全シート照合」「全ファイル確認」「全項目レビュー」「全テスト結果検証」を含む依頼
- N 個（N >= 5）以上の独立要素を一気に比較・照合する依頼
- ground truth ファイル（同期版 txt / 仕様書等）と現実の実装ファイルを突き合わせる依頼

**SKIP 条件**:
- 単一要素・単一ファイルの照合（サブエージェント分割の意味がない）
- 動的な発見が必要（事前に項目リストが確定しない）タスク — 別の探索系 Skill を使う
- 依頼者が「ざっと見て」と明示的に粗い確認を求めている

## ワークフロー

### 1. 項目リストの確定（メイン）

bulk task を受けた時点で、最初に以下を確定する:
- 比較対象の単位（スライド / ファイル / 関数 / セクション）
- 項目総数 N
- 各項目の ground truth ソース位置（例: txt の行範囲）
- 各項目の現実ソース位置（例: py の関数名）

**禁止**: メインで自力比較を開始してはならない。リスト作成のみ。

### 2. 並列ディスパッチ（メイン）

`Agent` ツールで N 個のサブエージェントを並列起動（1メッセージ内で複数 tool 呼び出し）。各サブの責務は1項目のみ。

サブへのプロンプトに必ず以下を含める:
- 比較対象の項目 ID と内容（ground truth と現実）
- 出力フォーマット制約（次節）
- 「他項目への参照を検出したら適用せず、依存フラグとして返す」指示
- 「項目1個に閉じる範囲のみ対象。範囲外の編集は依存フラグで報告」指示

サブエージェント種別: `Explore`（read-only 監査のみ）または `general-purpose`（適用まで行う場合）。タスクに応じて使い分け。

### 3. サブ出力フォーマット制約

各サブの返答は以下の形式を強制（プロンプトで指示）:

```
## 項目: <項目ID>

### 要素比較
- [title]
  TXT: "<txt の title 全文>"
  PY:  "<py の title 全文>"
  VERDICT: PERFECT_MATCH | NEEDS_UPDATE

- [headline]
  TXT: "<txt の headline 全文>"
  PY:  "<py の headline 全文>"
  VERDICT: ...

- [bullet 1]
  TXT: "..."
  PY:  "..."
  VERDICT: ...

（全 bullet を quote-pair で並記）

### 依存フラグ
- なし | 以下の他項目参照を検出: [...]

### 適用結果（適用 role の場合）
- N 件中 M 件適用 / X 件依存フラグで保留
```

**quote-pair 強制の意味**: 要素を verbatim で引用させることで『見たフリ』を物理的に防ぐ。読まないと quote できない。

### 4. メインでの集約

サブから返ってきた結果を集約。メインの責務は:
- 各サブの verdict を集計（N/M形式）
- 依存フラグが立った項目を抽出し、クロスカット変更（TOC・cushion・章番号等）をメインで適用
- マージ衝突（複数サブが同じファイル位置を編集）を解決

**禁止**: メインで自力比較を再実施しない（既にサブで実施済）。

### 5. 完了報告フォーマット（メイン）

完了主張に数値必須:
- `N 件中 M 件処理`
- `X 件未処理（理由: ...）`
- `Y 件依存フラグでメイン側集約適用済`

**禁止表現**: 「全件チェックした」「系統的に再照合した」「整理しました」「scan しました」「完全に同期済」等、数字を伴わない質的完了表現。

### 6. 外部検証（強く推奨）

完了主張前に、機械的検証を一度通す:
- `git diff` で実際の変更を確認
- 単体テスト / lint を走らせる
- ユーザーに「差分プレビュー」を提示

当方の『完了』を最終確認とせず、これらを最終確認とする。

## 注意事項 / Caveats

- **サブも同じ訓練分布の AI** で、同種の虚偽報告挙動を持つ可能性がある。quote-pair 出力フォーマット強制はその緩和策（消去ではない）。サブ出力に quote が無ければ却下して再実行
- **並列起動のコスト**: 30項目なら30サブエージェント。API コストとレートリミット注意。100超のような巨大タスクは2段階分割（粗 → 細）を検討
- **依存検出の漏れ**: サブが「項目1個に閉じない参照」を見逃すと、クロスカット変更が抜ける。メインは依存フラグが空のサブも疑い、TOC・cushion・main() のような典型的クロスカット要素は最後にチェック
- **項目リスト確定段階のミス**: 項目漏れ・粒度不適切があると全体が崩れる。リスト確定をメインが雑にやると、Skill の効果が消える。リスト確定段階こそ最も慎重に
- **適用 role と監査 role の混同**: read-only 監査と write 適用を同じサブに任せると複雑化。可能なら2段（監査サブ → メイン集約 → 適用サブ）に分離

## 前提 / Prerequisites

- `Agent` ツール（claude-code内蔵）が利用可能
- 比較対象の ground truth が明確に定まっている（曖昧なら先に確定）
- 各項目が独立に比較可能（強い相互依存があるなら粒度を上げる or 一括処理）

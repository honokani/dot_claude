# Slide Writing

pptxスライドを段階的に作成するスキル。Google Slidesでの利用を前提とする。

## 前提

- 出力形式: pptx
- 利用環境: Google Slides（pptxをインポート）
- python-pptx を使用してプログラマティックに生成
- **基本フォーマットの生成器（test_layout.py）が同ディレクトリに存在する。スライド生成時はこのコードのヘルパー関数群（add_title, add_headline, add_separator, add_table, add_background 等）をそのまま使用すること。自前で再実装しない。**
- **背景画像はオプション**。`add_background(slide, image_path)` を呼ぶと指定画像をスライド全体に敷いて最背面に押し下げる。`image_path` が `None` または存在しない場合は何もしない（従来通りの白背景）。プロジェクトごとに使う・使わないを判断する。

## 作成手順（3フェーズ）

### Phase 1: 目次（スライドタイトル一覧）

全体構成を見渡すため、最初にスライドタイトルの一覧を作成する。

**手順:**
1. ユーザーからテーマ/要件を受け取る
2. スライドタイトルの一覧をテキストで提示する
3. **承認ゲート**: ユーザーの承認を得てからPhase 2に進む

**タイトルの書式:**
- 実ページ（内容スライド）のタイトルは `■ ` で始める（例: `■ 市場環境の分析`）
- 目次・セクション区切り等のタイトルには `■ ` を付けない

**出力形式:**
```
1. [目次]
2. ■ タイトル1
3. ■ タイトル2
...
```

### Phase 2: ヘッドライン

各スライドのメッセージ（ヘッドライン）を確定する。

**ヘッドラインの形式要件:**
- タイトル直下に配置
- 100文字前後
- 2行に収まるように（改行なしで記述、表示上の折り返しのみ）
- 1スライド1メッセージ（複数メッセージを混ぜない）

**ヘッドラインの質的要件:**
- 「以下の通り」は絶対NG（受け手に解釈を委ねている＝文字が書いていないのと同義）
- 「XXX市場の市場規模はYYYY億円」のような解釈なしの事実のみもNG（大きいのか小さいのか見る人によって解釈が異なる）
- 事実 + 解釈（So What?）を含めること
- 解釈の4類型を意識する:
  1. 多い/大きい（ポジティブ表現）
  2. 少ない/小さい（ネガティブ表現。なるべく言い換えで排除が望ましい）
  3. 最小でもXXより多い
  4. 最大でもXXより少ない
- 3行以上はNG（2メッセージ混在 or 「自分が調べたこと全部書く」の兆候）。ただしプロポーショナルフォントのため文字数での厳密制御は不可能。気持ちで2行を目指し、最終的には目視確認
- **末尾の「。」は付けない**（test_layout.pyのadd_headlineが自動除去する）
- 2文構成の場合は文間の論理関係（因果、前提、並列等）を明確にする

**1スライド1メッセージの違反パターン:**
- 並列関係にある複数メッセージを1スライドに詰め込む
- 階層の異なる要素（上位メッセージとその下位ファクト）を1スライドに混ぜる

**手順:**
1. Phase 1で承認されたタイトル一覧に対し、各スライドのヘッドラインを記述
2. テーブル形式で提示:
   ```
   | # | タイトル | ヘッドライン |
   |---|---------|------------|
   | 1 | ...     | ...        |
   ```
3. **承認ゲート**: ユーザーの承認を得てからPhase 3に進む

### Phase 3: 内容充実（ボディ作成）+ pptx生成

承認されたタイトル・ヘッドラインに基づき、各スライドのボディを作成してpptxを生成する。

**スライド構成要素:**
```
+------------------------------------------+
| [ナビゲーター]（任意）                      |
+------------------------------------------+
| タイトル                                   |
+------------------------------------------+
| ヘッドライン（メッセージ）2行以内             |
+------------------------------------------+
|                                          |
|  ボディ                                   |
|  +--------+  +--------+                  |
|  |パネル1  |  |パネル2  |                  |
|  +--------+  +--------+                  |
|                                          |
+------------------------------------------+
| フットノート / 出典                         |
+------------------------------------------+
```

**ピラミッド構造の遵守:**
- メッセージとボディは「So What? / Why So?」の関係
- パネル内のコンポーネントも同様にピラミッド構造
- どのレイヤーでも上位と下位が論理的に紐づくこと

## 内容充実ルール

### 基本方針

**デフォルトは箇条書きと表。** 視覚効果が必要な場合のみ、引き出しからチャートを出す。

#### ボディ表現の選択フロー

```
ヘッドラインを支えるボディの内容は何か？
│
├─ 主張・説明・補足の列挙 ─→ 箇条書き
├─ 項目×属性の整理 ─────→ 表
│
└─ 上記では情報の関係性が伝わらない
   │
   ├─ 扱う情報は定量か？
   │  │
   │  ├─ 時間軸に沿った変化を見せたい
   │  │  ├─ 単一項目の推移 ──────→ 縦棒グラフ
   │  │  ├─ 傾向/トレンド ──────→ 折れ線グラフ
   │  │  └─ 構成比の推移 ──────→ 積み上げ棒グラフ
   │  │
   │  ├─ 並列項目を比較したい ────→ 横棒グラフ
   │  ├─ 施策による増減を見せたい ──→ ウォーターフォール
   │  ├─ 2変数の相関/分布 ────→ 散布図
   │  └─ 頻度分布 ─────────→ ヒストグラム
   │
   └─ 扱う情報は定性か？
      │
      ├─ 特定テーマに該当する？
      │  （組織/ロードマップ/業務フロー/ビジネスモデル/
      │   バリューチェーン/論点・検討アプローチ）
      │  └─ YES → テーマ特化チャート（汎用4種の派生）
      │
      └─ 汎用チャートから選択
         ├─ 概念を分解したい ────→ ツリー
         ├─ 要素間の構造/依存を示したい → インフルエンスダイアグラム
         ├─ 2軸で分類+象限間の移動 ──→ マトリクス
         └─ 複数項目を軸で比較/絞り込み → テーブル（表に戻る）
```

**判断の指針:**
- 迷ったら箇条書き/表に戻る。チャートは「これでないと伝わらない」場合の手段
- 「単なる要素分解」はウォーターフォールではなく積み上げ棒（または表）
- 「並列項目」は縦棒ではなく横棒（縦棒は時系列に見える）
- 円グラフは使用不可（最適解になるケースがない）

#### 箇条書きのルール
- 1項目1主張。修飾を削り、事実+解釈を簡潔に
- 階層は2段まで（3段以上はスライド分割を検討）
- 並列する項目は同じ粒度・同じ文体に揃える

#### 表のルール
- 列タイトル必須。一列一意（同じ列に違うレベル感の内容を混ぜない）
- 「概要」「内容」「備考」等のあいまいな列名は原則禁止（論理不整合の温床）
- 列名はヘッドラインと連動させる

### 引き出し: チャート選択（視覚表現が必要な場合のみ）

箇条書き/表では不十分と判断した場合に、以下から選択する。

#### 選択の手順
1. 「情報処理の種類」を特定（洗い出し / 関係性把握 / 絞り込み）
2. 「扱う情報の種類」を特定（定量 / 定性）
3. 上記2軸からチャートを選択

#### 定量チャート（8種）

| # | チャート | 用途 | 注意 |
|---|--------|-----|------|
| 1 | 縦棒 | 時系列変化 | 並列比較には横棒を使う（時系列に見える） |
| 2 | 折れ線 | 推移・傾向 | 傾向→マーカー不要、具体数値→マーカー必須 |
| 3 | 横棒 | 並列項目比較 | 並び順は降順/昇順/カテゴリに従う |
| 4 | 面積図 | 時系列の構成変化 | - |
| 5 | 積み上げ棒 | 構成比の変化 | 平行移動が少ない順序で配置 |
| 6 | ヒストグラム | 頻度分布 | - |
| 7 | ウォーターフォール | 施策による変化 | 単なる要素分解には積み上げ棒を使う |
| 8 | 散布図 | 相関・分布 | - |
| - | 円グラフ | **使用不可** | - |

**定量チャート共通ルール:**
- 出典必須（第三者が参照可能な粒度）
- 縦軸0始まり、各軸に単位記載
- 目盛り/補助線と数値ラベルの重複回避
- 複数種別を混ぜた"独自"チャート禁止

#### 定性チャート（10種）

**汎用4種:**

| # | チャート | 得意な処理 | ポイント |
|---|--------|---------|--------|
| 1 | テーブル | 比較、絞り込み | （表のルールに従う） |
| 2 | マトリクス | 比較、絞り込み | 2軸は独立。象限間の移動を記述 |
| 3 | ツリー | 分解、構造把握 | 分解ロジックを明示（四則演算等） |
| 4 | インフルエンスダイアグラム | 構造把握 | ノード/エッジの意味を明確化。「それっぽく配置しただけ」はNG |

**テーマ特化6種（汎用4種の派生）:** 組織図、ロードマップ、業務フロー、ビジネスモデル、バリューチェーン、論点/検討アプローチ

### パネル設計

パネル = ボディ内の論理的なまとまり。表現方法（箇条書き/表/チャート）を選んだ後、補完情報と合わせてどこに配置するかを決める。

#### 典型パターン

| 情報処理 | パネル構成 |
|--------|---------|
| 洗い出し（分解） | 左: 構造 / 右: 説明補足 |
| 洗い出し（一覧化） | 左: 構成 / 中: 施策一覧 / 右: 効果 |
| 関係性把握（構造） | 左: 構造図 / 右: 各要素の説明 |
| 関係性把握（差分） | 左: 対比 / 右: 説明補完 |
| 絞り込み（比較） | 左: 評価軸+比較+評価 / 右: 結果説明 |
| 試算結果 | 左: 前提 / 右: 結果+解釈 |

### 3. レイアウトチェック（3原則）

#### 原則1: 左上から右下
- 視線は左上→右下に動く。説明の順序に沿って左から配置する
- **NG例**: 凡例（最初に読むべき情報）がスライド右端に配置されている
- チェック: 読者が最初に見るべき要素が左上にあるか確認

#### 原則2: 縦/横いずれか一方向への展開
- パネルは縦方向または横方向のいずれか一方向にのみ展開する
- **NG例**: 左パネルが大きく、右側に上下2パネル（定量チャート+解釈+ネクストステップ）が縦横混在で配置
- チェック: ボディの読み順が一方向に流れているか確認

#### 原則3: 並列関係にあるものの大きさを揃える
- パネルレベル: ASIS-TOBEの対比パネルは同じサイズにする
- オブジェクトレベル: オプション洗い出し・構成要素分解のボックスは同じサイズにする
- **NG例**: ASISとTOBEを対比して差分を論じるのが主眼なのに、一方が他方より大きく描かれ対比関係が視覚的に伝わらない

### 4. 情報のハイライト

#### 手順（3ステップ）

**Step 1: 白黒で作成**
- 枠線: 黒または無し
- 塗りつぶし: 白
- まず内容・構造の正しさを確認する

**Step 2: ハイライトを付ける**
- 使用する変数: 色、枠線、太文字、下線
- **強弱の両ベクトルを使い分ける**: 強調（赤・太字）だけでなく、非強調（グレーアウト等）も使う
- **単一の軸に複数表現を併用しない**: 例えば「重要」を示すのに赤文字+太文字+下線を同時に使わない

**Step 3: 視線の誘導を確認する**
- ページを切り替えた瞬間にスライドのどこに視点が行くか確認
- メッセージの核心部分に着目されるよう、余計な色を間引く

#### ハイライトのNGパターン

| NGパターン | 問題 | 視覚的な症状 |
|----------|-----|---------|
| 複数の強調方法の混在 | どの情報に着目すべきか不明 | 斜字体/太文字/青文字/オブジェクト塗りつぶしが同時に存在 |
| メッセージと無関係な情報の強調 | 視線がメッセージから逸れる | ヘッドラインと無関係な数値や項目が赤字 |
| チャートごとに強調色が異なる | 色の意味が不統一 | 左のチャートは赤が強調、右のチャートは緑が強調 |
| 複数の情報種別の混在 | 情報密度が高すぎる | テキスト/写真/画面イメージ/ピクトグラムが1スライドに混在 |
| 2スライドに分けるべき内容の混在 | 1スライド1メッセージ違反 | ユースケースのポイント＋導入実績が同一スライド |

### 5. セルフチェック

スライド完成後、以下の順に確認する:

| 順序 | 方法 | チェック事項 |
|-----|------|---------|
| 1（優先） | プレゼン: 1ページ1分程度で声に出して説明 | 情報が左上から右下に流れるか / メッセージ・キーフレーズが適切に強調されているか |
| 2 | 早送り: 1ページ1秒程度で切り替え | 見た瞬間にそのページの情報処理（＝何のチャートか）が伝わるか / 着目してほしい情報に視線が誘導されるか |
| 3 | 誤脱確認: 単語/文/オブジェクト単位で視線を動かす | 誤字脱字がないか / クライアントに伝わりやすい表現か |

## ビジュアルデザイン方針

**ミニマル + 情報密度優先。** 装飾を削ぎ落とし、空白より情報を優先する。

### 原則
- 不要な装飾・グラデーション・影・3D効果は使わない
- 色数は最小限（黒+グレー+強調色1色が基本）
- フォントは1種類。ウェイト（太さ）で階層を表現
- 罫線・枠線は構造を示すために使う。装飾目的では使わない

### マージン・余白
- **タイトル〜スライド上端**: 詰める。大きなマージン不要
- **タイトル〜ヘッドライン**: 詰める。タイトルとヘッドラインは一体で読むもの
- **ヘッドライン〜ボディ**: 区切りとして最小限の余白のみ
- **ボディ内**: 情報を詰め込むためにパネル間の余白も最小限
- **フットノート**: スライド下端に寄せる
- 要約: 空白の美は追求しない。情報が入る余地があるなら情報を入れる

### フォントサイズ・色
| 要素 | サイズ | 色 |
|------|-------|-----|
| タイトル | 24pt 太字 | 黒 |
| ヘッドライン | 14-16pt 動的（~82文字→16pt, 83-85→15pt, 86~→14pt） | ダークグレー |
| ボディ（横線より下は全て） | 14pt | 黒 |
| フットノート | 8pt | グレー |

### 表のスタイル
- 表はpptxの表機能で作る（n*mの長方形オブジェクト整列は最終手段）
- ヘッダー行: 背景 濃紺 / 文字 白 / 太字
- データ行: 背景 白 / 文字 黒 / 通常
